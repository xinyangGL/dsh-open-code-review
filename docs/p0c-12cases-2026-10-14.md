## 本轮改的东西（v0.12.2，未发版）

- `lib/client.js` 回合尾部入口原来是
  `if (feedReady && (changesSeq === null || hasChanges !== true)) return null;` ——
  「宿主有改动服务、但这一回合没留下改动记录」被当成「本回合没改动」，入口被**藏掉**，
  与同一段代码顶部注释承诺的 fail-open 相反。改成
  `if (feedReady && hasChanges === false) return null;`：只有**明确读到 `total=0`** 才隐藏。
- 单测：`test/client-smoke.mjs` 里「本回合没有改动记录」的断言从「按钮不出现」改成「按钮出现（按不知道处理）」。
- 全套：smoke 321 / killswitch 44 / host-contract 37 / job 51 / reviewer 45 / bridge 104 / client-smoke 214 / cordis-inject + `test:pack` 全过。

### 这一轮顺手发现的两条**偏差（未改代码，只登记）**

1. **取消后进度行的文案是 ocr 的原始 detail**：`cancelled by the user（OCR_ABORTED：…）; cancelled by the user`
   —— 英文与中文重复、也没有 §7.1/附录 A 要求的「本次没有结论 + 已经产生的用量照常计费」。
   结论文本（`valueToText`）那一侧是对的（v0.12.4 的 M8 + v0.12.5 的 `FAILURE_ONE_LINERS`），**进度行这一侧没有对齐**。
   落点：`lib/index.js:584 finishReviewJob()` 用的仍是 `code：summary`，而 `summary` 里带着 ocr 的 stderr 原文。
2. **停止是两连击但没有任何提示**：第一击只武装（`data-ocr-stop-armed`），界面上没有出现「再点一次」或后果句的可见变化
   （后果句在词表里、规格 §7.1 也要求它在第二击前出现）。脚本这次是靠「点两次」试出来的，普通用户可能以为按钮坏了。
