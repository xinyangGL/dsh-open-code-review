# P0-C：12 条回归用例（脚本化 + 真机，2026-10-14）

> 口径来自 CPO 专家（全文：`40b1814ff541-summon_experts.txt` 第 602 行）：
> **4 入口 + 3 失败路径 + 5 边界 = 12 条**；按钮路径只要有 1 条失败就**不发布**。

## 本轮改的东西（v0.12.2，未发版）

- `lib/client.js` 回合尾部入口原来是
  `if (feedReady && (changesSeq === null || hasChanges !== true)) return null;` ——
  「宿主有改动服务、但这一回合没留下改动记录」被当成「本回合没改动」，入口被**藏掉**，
  与同一段代码顶部注释承诺的 fail-open 相反。改成
  `if (feedReady && hasChanges === false) return null;`：只有**明确读到 `total=0`** 才隐藏。
- 单测：`test/client-smoke.mjs` 里「本回合没有改动记录」的断言从「按钮不出现」改成「按钮出现（按不知道处理）」。
- 全套：smoke 321 / killswitch 44 / host-contract 37 / job 51 / reviewer 45 / bridge 104 / client-smoke 214 / cordis-inject + `test:pack` 全过。

## 诚实登记：还差什么

- **#1 必须在按钮真的渲染出来的环境里做**：要么先修掉上面那条第一方 turnTail 崩溃（与本插件无关），
  要么请用户在桌面宿主里点一次按钮。**在那之前「按钮路径」不能算通过。**
- #3/#4 需要有可用的键盘输入通道（bsk 的 `fill` 对 contenteditable 生效但提交没生成回合）。
- #11 需要用户重启；#12 需要用户的计费同意。
- **macOS 未验证**：本机没有干净 macOS 机器，不冒充双平台。
