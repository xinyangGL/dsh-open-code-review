# 评审体验交互规格（dsh-open-code-review）

- 基线：`HEAD 34a98e0`（2026-10-13 15:29，工作区干净）。本文行号以此提交为准。
- 范围：只覆盖「代码审核」这条线；**不新增功能面**，只做交互修复。凡属新功能面或需要产品拍板的，标 `[需确认]`。
- 分级：`[必须]` ＝ 现在的交互在「说做不到的事」或「该说的没说」，改文案/排序/显隐即可、零新通道；`[可选]` ＝ 体验增益，可延后；`[需确认]` ＝ 需先拍板（与 `docs/ROADMAP.md` §4/§5 的既有边界相关）。
- 本文不贴源码；只引用文件与行号，以及**用户可见的文案原文**。

## 0. 结论摘要（先看这一段）

现有交互骨架是对的：4 个入口、4 个可见面、进度与代价都有落点、失败码有统一出口。真正难受的是四处**「承诺与事实不一致」**，都能在不动功能面的前提下修：

| # | 病症 | 判定 | 一句话修法 |
|---|---|---|---|
| ① | 范围「说了做不到」：命令提示、工具说明、README 三处都暗示能「只审某些路径」，但默认档（workspace）根本不把路径交给 ocr | `[必须]` | 默认档显式拒绝 + 说清；能过滤的档（delegate）显式申报；真过滤 `[需确认]` |
| ② | 代价「点前不可见」 | `[必须]`（部分）+ `[需确认]`（整块） | 已有数据可做「本回合改动数 + 引擎代价标签」；真正的 ocr 规模预估要宿主侧新通道 |
| ③ | 入口「会在没得审的回合出现」：脏检查 fail-open，且 `total>0` ≠ 可审 | `[必须]`（文案） | 保留 fail-open（`docs/ROADMAP.md` §4 要求），但按钮说明与空态要预置「可能没有可审内容」 |
| ④ | 结论「层级倒置」：命令/仓库/会话/文件清单排在结论之前，原始 JSON 位置随结果漂移 | `[必须]` | 结论行提到第 1 段，出处降到第 5 段，附录固定到最后；面板化 `[需确认]`（`docs/ROADMAP.md` §4/§5 已定不做） |
| ⑤ | 设置页「工程化」：内部术语外露（entry id / mode / writable / 键名） | `[必须]` | 正常态一律人话，内部字段只在异常时外露 |

**可行性边界（决定哪些修法不用等）**：客户端只有三条通道 —— 宿主命令 `remote.commands.execute`（`lib/client.js:1610`）、`session` 命名空间（`lib/client.js:804-809`）、宿主只读路由 `fetch`（`lib/client.js:1719`）；插件自身**没有注册任何 remote**（`lib/index.js` 全库无注册点）。所以凡是要让客户端拿到 ocr 的规模/成本，一律等于新增宿主侧通道＝新功能面；凡是把已有数据换个位置显示，都是纯交互修复。

## 2. 状态机

### 2.1 回合尾按钮（客户端）

状态：`hidden` → `ready` → `busy` → `done` / `error`。

| 转移 | 条件（行号） |
|---|---|
| → hidden | 宿主缺 `useJobs`/会话 id（守门 `lib/client.js:1681-1683`）；`enabled===false`（1737）；`onDemand!==false` 不成立（1738）；feed 就绪但没有本回合变更坐标（1739）；feed 就绪且 `hasChanges!==true`（1740） |
| → ready | 以上全过 → 主行 `tail.start`＝「启动代码审核」（`lib/client.js:249`） |
| → busy | 同一会话存在 live 的 `ocr-review` job（`lib/client.js:1741-1742`）→ `tail.running`＝「正在评审…」（250） |
| → done/error | 命令返回 `{ok,text}`（`lib/client.js:1743-1772`）→ 文案落在按钮旁那一行（1771） |

硬事实（决定 ③ 的量级）：

- 变更数来自宿主只读路由的 `data.total`（`lib/client.js:1712-1734`）；
- 读不到（异常/404/非整数）**一律当作「有改动」**（fail-open，`lib/client.js:1724-1730`）；
- `total>0` 只说明「有改动」，不说明「可审」；「不可审」的判定在宿主侧（`lib/index.js:787-801`）。

`[必须]` 要补齐的转移：

- `ready` 增加副行信息（本回合改动数 + 引擎代价标签），把「点前已知」从 0 项提到 2 项；
- `busy` 明确「进度去哪看」并给出「要停去哪停」（现状零提示）；
- `error` 必须带「下一步/去哪修」，而不是只给码（现状 `tail.failed`＝「评审没能启动。」，`lib/client.js:254`，零信息）。

### 2.2 一次评审的 job（宿主）

状态：`running`（首行 phase + 每 30 秒心跳）→ `settled`（`completed` / `failed` / `killed`）。

- 标题：`评审 · <范围短语> · <仓库目录>`（`lib/index.js:556`）；范围短语＝工作区改动／提交区间 X..Y／提交 abc1234／整文件扫描（`lib/index.js:521-527`）；自动评审前缀「自动评审」（同 556）。
- 首行：`… ｜ 启动（引擎 ocr）`（`lib/index.js:574`），后接运行说明（`lib/index.js:728-730`）。
- 心跳：30 秒一次（`HEARTBEAT_MS` `lib/index.js:620`；`startHeartbeat` `lib/index.js:627-637`），文案由 `heartbeatLine` 给（`lib/review.js:81-90`）。
- 结果 detail：`失败：<码>：<摘要>` 或 `已完成（Xm Ys）`（`lib/index.js:583-588`）。
- 超时预算：分钟数 + 60 秒宽限（`lib/review.js:257`）。
- 输出缓冲超过 512K 只留尾巴（`lib/index.js:596-614`）→ 进度文案不依赖完整输出。

### 2.3 进度行（客户端）

状态：`live(running)` / `live(stopping)` / `settled(completed|failed|killed)` + **60 秒余辉**。

- 最多显示最近两条（`lib/client.js:1519-1521`）；1 秒 tick（1524-1528）；`<60s` 显示 `Ns`、否则 `Xm Ys`（1489-1495）。
- 停止：两连击，4 秒武装窗口（1529-1544）；武装中显示「再点一次停止」（`lib/client.js:244`）。
- 状态词：运行中／已完成／失败／已停止／停止中…（`lib/client.js:1480-1486`）。

### 2.4 设置页

- 高级区默认收起（`lib/client.js:1175`）；收起态给 `advanced.collapsedHint`（「低频参数已收起（模型路由 / 独立评审 agent / 评审时机）。默认值对多数人够用；要改就点上面的标题展开。」`lib/client.js:179`）。
- 脏值：单条出「保存改动／撤销此条／恢复默认」（`lib/client.js:1329-1335`），顶部出「保存改动」（1412）；高级折叠头带待保存计数（1431-1433）。
- 只读诊断区列 15 个隐藏键（`lib/client.js:1377-1395`）；摘要区列 entry id / status / mode / writable / LLM 路由（`lib/client.js:1350-1362`）。

## 3. 关键用户旅程

### J1 首次使用（装上插件之后的第一次评审）

现状链路：装好 → 打开设置页看到 4 项基础设置 → 想评审只能 (a) 等模型按 skill 自己调工具（skill 可能没注册上，`lib/index.js:1787-1806`）、(b) 敲 `/ocr-review`、(c) 点回合尾按钮（仅当有改动）。
断点：环境体检（ocr 是否安装、LLM 是否就绪）只有 `ocr_status` 一条路；按钮失败文案来自命令的错误分支（`lib/index.js:3115`／`3120`／`3125`／`3142`），**都不含安装指引**；安装指引只存在于 `ocr_status` 结果的 note 里（`lib/index.js:1815-1819`）。首次用户最常见的结局是一行「评审没能启动。」（`lib/client.js:254`）。

`[必须]` 目标文案（首次）：

1. 设置页 basic 区上方一段静态引导（纯文案，不需要新通道）：
   「三步开始：① 确认本机装了 ocr（`npm i -g @alibaba-group/open-code-review`）；② 在这里选一个模型名（走 DSH 的额度）；③ 改完文件后点回合尾部的「启动代码审核」。」
2. 首次点击失败时，按钮旁那一行必须是**「环境问题 + 下一步」**，例如：
   - 「没能启动：本机找不到 ocr 可执行文件。→ 安装 `npm i -g @alibaba-group/open-code-review`，装完再点一次。」
   - 「没能启动：模型密钥没走通（OCR_LLM_MISSING）。→ 设置 → 代码评审 → 模型名 选一个，或写入密钥。」
3. 禁止无信息的失败文案：「评审没能启动。」（`lib/client.js:254`）只作最后兜底，且必须拼上宿主给的原因。

### J2 日常「改完就评」（主路径）

| 时刻 | 现在发生什么 | 用户该看到什么（建议文案） | 判定 |
|---|---|---|---|
| 回合结束 | 有改动 → 按钮出现（`lib/client.js:1737-1740`） | 主行「启动代码审核」；副行「本回合 3 个文件改动 · ocr 流水线（每文件 3~6 分钟、按 tokens 计费）」 | `[必须]` 副行是新信息；其余沿用现状 |
| 点击 | 执行 `/ocr-review --entry=button`（`lib/client.js:1610`），宿主回 `lib/index.js:3144` | 「已让模型执行一次代码评审：范围＝未提交的工作区改动，引擎＝ocr（每文件 3~6 分钟、按 tokens 计费）。进度看输入框上方；结论会出现在这一回合的回复里。」 | `[必须]`：现状没说范围/代价/去哪看进度 |
| ≤1s | job 建立，进度行出现首行（`lib/index.js:556`、`574`） | 首行保留；补「超时 N 分钟，到点会问你要不要停」 | `[可选]` |
| 首帧 | 跑前预估与口径（`lib/index.js:718-730`：预估规模、超时下限、LLM 真实耗时口径） | 现状保留（全链路信息密度最高的一处，别动） | 保留 |
| 每 30s | 心跳三档（有成本／有超时／无预估，`lib/review.js:81-90`） | 现状保留 | 保留 |
| 结束 | 结果文本（`lib/review.js:961-1008`） | 按 §5 重排：第 1 段是结论行 | `[必须]` |
| 结束 + 60s | 进度行消失（`lib/client.js:1457`） | `[可选]`：结论出现前不要消失，或余辉延到「下一回合开始」 | `[可选]` |

### J3 长评审（默认档按 tokens 计费，真机 176~600 秒/文件）

现有时间语义（落点都有，缺的是「该变文案时只变了秒数」）：

- 20 秒后才开始显示「已用时」（`lib/review.js:81-90`）；
- 剩余量估算只在有预估时给（`lib/review.js:109-116`）；
- 超过下限前的提醒（`lib/review.js:148-154`）；
- 超过上限后的动作「继续等，或点上面的「停止」只保留当前结论」（`lib/review.js:109-116`）；
- 慢任务的静态口径（真机 176~600 秒/文件、scan 单文件约 0.16 美元，`lib/review.js:162-169`）。

`[必须]`：

- 越过预估下限时进度行**文案要变**（不是只让秒数跳），在 `heartbeatLine`／`remainingText` 的同一行给出动作，别让用户自己去找「停止」在哪。
- 停止的后果必须在点之前说（见 §7）。

`[可选]`：长评审期间把「换档更快」的出口（delegate／缩小范围）贴到进度行第二行。

### J4 失败

现状：失败在三个地方各自为政 ——

- 进度行：`失败：<码>：<摘要>`（`lib/index.js:583-588`）；
- 按钮旁：一行窄文本（`lib/client.js:1771`，单行省略 + `title` 全文）；
- 正文文本：`code`/`summary`/`nextStep`（`lib/review.js:961-1008`；`nextStep` 只在失败态出现）。

`[必须]`：把「码 → 一句话 → 下一步 → 能否重试」做成**同一段**，三处共用同一份文案（宿主侧 `NEXT_STEPS` 已有映射，`lib/review.js:39-58`）。按钮旁那行只放「码 + 一句话 + 去处」（它放不下完整下一步，别硬塞）。

### J5 无改动 / 有改动但不可审

两个空态必须分开，措辞不能互相污染：

| 场景 | 现在 | 目标 |
|---|---|---|
| 本回合没有改动 | 按钮不出现（`lib/client.js:1740`）—— 这是设计（`docs/ROADMAP.md` §4 禁止灰色常驻按钮） | 保持不出现；正文也不需要提示 |
| 工作区确实没有任何未提交改动，但用户**主动**要求评审 | 有误报风险：`reviewedFileCount` 逐级回落（`lib/index.js:480-494`），在「没有改动、也没有排除项」时可能打出「审查 N 个文件，未发现问题」 | `[必须]` 显式空态：「本次没有未提交的改动，没有需要评审的内容。要审别的范围：`/ocr-review` 提交 `<sha>`，或指定路径。」 |
| 有改动，但改动文件全被排除（不可审） | v0.11.2 已力挽：明确说「本次没有可审的代码改动：N 个改动文件都被排除（…）」且**禁止**「未发现问题」（`lib/index.js:782-801`、`844-852`；口径注释 `lib/index.js:754`、`783`） | 保持；并把下一步（换 scope／显式给 paths，`lib/index.js:851`）从 notes 提到结论第 1 段之后 |

`[必须]`（③ 的收尾）：既然脏检查刻意 fail-open，按钮说明就必须预置「点了可能被告知没有可审内容」。建议 `title` 补：「按需跑一次代码评审；若本回合只有被排除的文件类型，会直接告诉你没有可审内容。」

## 4. 评审范围与代价：可控点放在哪

**设计原则**：范围（审什么）在默认档不要让用户选；代价（要花多少）在默认档不要让用户估。可控点只放两处 —— **点前一行代价标签**（零成本）、**失败/超时后的一个「下一档」**（点后一次跳转）。

### 4.1 四层可控点

| 层 | 位置 | 放什么 | 现状证据 | 判定 |
|---|---|---|---|---|
| L0 默认 | —— | 范围＝未提交的工作区改动（`lib/index.js:2039`）；引擎＝ocr（`lib/client.js:109`） | 已有 | 保持 |
| L1 点前 | 按钮副行 | 本回合改动数（`data.total`，`lib/client.js:1726`）＋ 引擎代价标签（引擎值来自设置快照，`lib/client.js:1697`；文案见 `CHOICE.engine`，`lib/client.js:38-83`：ocr「每文件 3~6 分钟、按 tokens 计费」／delegate「不调 LLM，几秒」） | 目前按钮上零信息 | `[必须]` |
| L2 点后首帧 | 进度行 | 预估规模、超时预算、LLM 真实耗时口径、计费口径 | 已有且密度很高：`lib/index.js:718-730`（预估取自 `lib/index.js:671-697`；文案 `lib/review.js:96-102`、`124-130`、`136-141`、`148-154`、`162-169`） | 保持，只需在按钮/命令文案里指向它 |
| L3 失败后 | 结论文本的「下一步」段 | 换 delegate、缩小范围、调大超时 | 已有：`NEXT_STEPS`（`lib/review.js:39-58`），只在失败时输出（`lib/review.js:1001`） | `[必须]`：见 §5 把它提到结论行之后 |
| L4 长期 | 设置页 | 引擎／自动评审／评审先于测试／模型路由 | 已有（basic 4 项 `lib/client.js:108-111`） | `[必须]`：只做文案人话化，不加新开关（`docs/ROADMAP.md` §4:84） |

**明确禁止的\"可控点\"**（会与现有边界冲突）：per-file 进度条、行号跳转、富文本结论卡（`docs/ROADMAP.md` §4:81）；灰色常驻按钮（§4:82）；把脏检查变成硬依赖（§4:83）；新的审批交互或新开关（§4:84）；自动重试/换模型容错（§4:80）。

### 4.2 范围 ① 的三种修法（含证据链）

问题不是「缺功能」，而是**三处文案都在暗示一件默认档做不到的事**：

- 命令输入提示写着「只审 src/ 下的改动」（`lib/index.js:3105`）——它是给用户的 placeholder；
- 工具参数说明写着 paths「也用于 delegate 模式的 git diff 过滤」（`lib/index.js:2044-2047`）；
- `README.zh.md:266-268` 给了 `/ocr-review 只审 src/ 下的改动` 这样的用法示例；
- 而默认档（workspace）拼给 ocr 的命令行里**不带任何路径参数**：`review` 档只拼 `--format/--audience/--color`（外加可选的 `--preview/--effort`，`lib/review.js:279-290`），公共尾只有 `--exclude/--rule/--provider/--model/--timeout`（`lib/review.js:264-269`）；只有 `scan` 档才传 `--path`（`lib/review.js:271-276`）。
- delegate 侧确实做过按路径收窄，但那是**插件自己做**的：git diff 收窄在 `lib/index.js:1025-1032`（`files: plan.paths`），渲染收窄在 `lib/index.js:1051-1053`（`only: plan.paths`，注释明确写「`ocr delegate preview` 没有 `--path`，清单永远是整个工作区的改动」），规格正文写「只看这些路径（paths 参数）」在 `lib/review.js:865`。

| 方案 | 做什么 | 代价 | 判定 |
|---|---|---|---|
| A 显式拒绝 + 说清 | 默认档给了 paths 时明确回「本次不支持按路径收窄，已按整个工作区评审；要按路径请用 scope=scan / engine=delegate」，同时改掉三处暗示性文案 | 纯文案 + 一处参数校验（`OCR_INVALID_ARGS` 通道已存在，`lib/review.js:18`、`40`） | `[必须]`（最小可用） |
| B 显式收窄 + 申报 | 插件自己按 paths 收窄 diff 与文件清单后再交给 ocr（复用 delegate 既有收窄：`lib/index.js:1025-1032`、`1051-1053`），并在结论里写「只看这些路径」 | 需要确认 ocr 在 workspace 档是否接受收窄后的输入语义 | `[可选]`／`[需确认]` |
| C 真过滤（ocr 原生按路径） | 依赖 ocr 是否支持 review 档的路径参数 | 未知，且 `docs/ROADMAP.md` §5:91 把「更灵活的评审范围」列在「待确认后才排期」 | `[需确认]` |

**推荐顺序**：先 A（消除「说了做不到」），B/C 等 `docs/ROADMAP.md` §5:91 拍板后再排。

### 4.3 代价 ② 的两半

| 半边 | 能否现在做 | 证据 |
|---|---|---|
| 「本回合有 N 个改动文件 · 默认引擎会按 tokens 计费」 | 能，零新通道 | `lib/client.js:1726` 已拿到 `data.total`；引擎标签可从快照取（`lib/client.js:1697`），文案复用 `CHOICE.engine`（`lib/client.js:38-83`） |
| 「这次大概几分钟 / 大概多少钱」 | 不能：ocr 侧规模预估要跑一次 `ocr delegate preview`（宿主侧 `lib/index.js:671-697`，8 秒超时），客户端点前没有这个通道 | 客户端只有 `remote.commands.execute`（`lib/client.js:1610`）、`session`（`lib/client.js:804-809`）、宿主只读 `fetch`（`lib/client.js:1719`）三条；插件未注册任何 remote |

### 5.2 目标层级（固定 6 层，顺序不随结果漂移）

1. **结论行**（新增，永远第 1 行）：一句话说清「有没有问题 / 有没有结论」。
   - 干净：`✅ 未发现问题 · 已审查 N 个文件（工作区改动 · ocr）`
   - 有问题：`⚠️ 发现 N 条问题（涉及 M 个文件）`
   - 部分结果：`⚠️ 部分结果：本次没有可审的代码改动 —— M 个改动文件都被排除（…）`
   - 无结论：`❌ 评审没有完成：OCR_TIMEOUT（…）`
2. **代价与规模**（现第 1/5/6 段合并）：`engine/scope/耗时/可审 N · 排除 M/用量与计费口径`。机读头行降级到这里（保留字段，但不再是第一行）。
3. **问题逐条**（现第 8 段，位置不变）：`文件 → 行 [严重程度]`，上限 40（`docs/ROADMAP.md` §4:83 不抬），超出给「其余 N 条见附录」。
4. **下一步**（现第 11 段，**成功态也要有出口**）：失败时用 `NEXT_STEPS`（`lib/review.js:39-58`）；成功但有 issue 时给「逐条处理后重跑：`/ocr-review`」；不可审时给「换 scope / 显式给 paths」（`lib/index.js:851`）。
5. **出处与可核对**（现第 3/4 段 + notes 里的覆盖回执）：实际命令、仓库、ocr 会话 id 与复看命令、覆盖率回执；独立评审 agent 行也归到这一层。
6. **附录**（固定最后）：delegate 规格正文、配置提示、备注、原始 JSON、stderr、截断提示。

### 5.3 折叠规则（文本语境的等价物）

- **永远不折叠**：结论行、代价与规模、下一步、空态/部分结果提示。
- **截断阈值保持现状**：可审文件清单 30 条（`lib/review.js:986`）、已排除 10 条（`990`）、问题 40 条（`963`、`995-997`）、原始 JSON 4000 字符（`1006`）；截断处必须给出「其余 N 条见 …」的同段指引（现状已做到，保留）。
- **原始 JSON 的触发条件放宽为「附录段始终存在」**：现状只在 `ok && engine==="ocr" && 无 issue` 时附（`1005`），导致「有 issue 时看不到原文」；目标是不改上限、只改位置与触发条件说明（§4:83 允许，不涉及 `maxIssuesInText`）。
- **长段落（delegate 规格 / stderr）**：放在附录最前，并在结论行下的第 2 层给一句「规格正文见文末附录」。
- **按钮旁那行窄文本**（`lib/client.js:1771`，单行省略 + `title` 全文）：只放「状态 + 去处」，例如 `已开始 · 结论见本回合回复` / `失败：OCR_NOT_FOUND · 下一步见回复`；**不承载结论**。

## 7. 进度与取消：时机

### 7.1 进度的时间轴（现状全部已有落点，缺的是「该变文案时只变了秒数」）

| 事件 | 时刻 | 现状 | 判定 |
|---|---|---|---|
| 进度行出现 | job 建立即出现（`lib/index.js:552-576`；客户端注册 `lib/client.js:1824-1842`） | 有 | 保持 |
| 首行 phase | 立即：`… ｜ 启动（引擎 ocr）`（`lib/index.js:574`）+ 运行说明（`lib/index.js:728-730`） | 有 | 保持 |
| 显示「已用时」 | 运行满 20 秒起（`lib/review.js:81-90`） | 有 | 保持 |
| 心跳 | 每 30 秒一次（`lib/index.js:620`、`627-637`） | 有 | 保持 |
| 剩余量 | 有预估时给「剩 N 分钟」（`lib/review.js:109-116`、`124-130`） | 有 | 保持 |
| 超时预警 | 距上限约 1 分钟时（`lib/review.js:148-154`） | 有 | `[必须]` 同一行补「停止后本次没有结论」 |
| 越过下限 | —— | 只跳秒数 | `[必须]` 文案要变（见下） |
| 硬超时 | 分钟数 + 60 秒（`lib/review.js:257`） | 有 | 保持（`-b/--resume` 不做，`docs/ROADMAP.md` §4:78-79） |
| 进度行消失 | 结束 60 秒后（`lib/client.js:1457`、`1519-1521`） | 有 | `[可选]` 延到结论出现/下一回合 |
| 只显示最近两条 | 一直（`lib/client.js:1521`） | 有 | 保持 |

`[必须]` 的三处文案时机：

1. **越过下限**：进度行从「运行中 · 已用 4m12s」变成带动作的句子，例如
   「正在评审 · 已用 4m12s（超过预估下限，可继续等，或停止后换 delegate/缩小范围再跑）」。
2. **进入停止武装**：武装态必须写后果，例如
   「再点一次停止（本次不会有结论；已经产生的用量照常计费）」。
3. **超时/取消之后**：结论文本第 1 层就是「没有结论」，不要只在备注里说。

### 7.2 取消：可用时机与语义

- **入口只有一个**：进度行上的「停止」（`lib/client.js:1535-1544`），两连击 + 4 秒武装窗口；按钮处没有取消。
- **取消的实际语义**：abort 传给子进程（`lib/index.js:552-576`、`536-546`）→ 结果是 `OCR_ABORTED`；ocr 的整条流水线是**一次性 JSON**，所以「没有结论、也没有留下 ocr 会话」（`lib/review.js:47-48`）。
- **不一致点（`[必须]`）**：超时分支明确说了「保住的只有已经花掉的用量」（`lib/review.js:45-46`），取消分支**没提用量**（`lib/review.js:47-48`、`lib/index.js:889-895`）。两条路径的花钱事实相同，文案必须一致。
- **不建议做的时机约束**：不要在「刚刚开始（<10 秒）」或「已经在收尾」时把停止按钮藏起来 —— 藏起来更糟（用户会不知道能停）。正确做法是**始终可用 + 点前说清后果**。
- `[可选]`：`busy` 态的回合尾按钮旁边给一句「要停止：输入框上方的进度行」；或直接在按钮旁提供同一个停止动作（复用同一个 kill 通道，`lib/client.js:1535-1544` 已有实现）。

## 10. 需要拍板的三件事（都引用 `docs/ROADMAP.md` §5 的「待确认」区）
