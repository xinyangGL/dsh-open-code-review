# 代码评审（阿里 OpenCodeReview）· DSH 插件

把你改过的代码交给 [阿里 OpenCodeReview](https://github.com/alibaba/open-code-review) 跑一次真实评审，并把结论原样带回来：**覆盖到哪些改动、用的哪个模型、为什么没跑成**。

- **不需要另外装 `ocr`**：二进制随插件安装（Windows x64）。
- **不需要配 API Key**：评审用你**当前对话正在用的模型**（经 DSH 的本机桥转发，密钥不进子进程）。
- **结论可核对**：每次都带「覆盖回执」——收录了哪些 hunk、哪些文件被排除、哪一部分没有结论。

## 30 秒上手

1. 安装（已装可跳过）：
   ```bash
   dsh plugin --profile <你的 profile> add github:xinyangGL/dsh-open-code-review
   ```
2. 改完代码，点回合尾部的 **「启动代码审核」**。按钮副行会先告诉你代价：`本回合 N 个文件改动 · ocr 档：约 3~10 分钟/文件、按 tokens 计费`。
3. 等它跑完看结论。想换入口：

| 入口 | 什么时候用 |
| --- | --- |
| 回合尾部「启动代码审核」 | 最常用；只在本回合有代码改动时出现 |
| `/ocr-review` | 想在命令里直接触发 |
| 对话里说「评审一下 / 检查这段改动」 | 模型按需调用 |

## 你会看到什么

**跑之前**：按钮副行写明本回合改了哪些文件、大概多久、是否计费。

**跑起来**：ocr 不吐增量进度，所以**没有进度条、也没有停止按钮**；工具调用行上能看到已用时长。想中断就停掉这一轮对话（已产生的用量不退还）。

**跑完**：结论固定六层，从上往下读就是一次交付——

1. **结论**——成功/失败、问题条数；干跑（preview）会明确写「没出结论」。
2. **覆盖与代价**——收录 x/y 个 hunk、哪些文件被排除、被截断的部分。
3. **问题清单**——`文件:行 [严重度]`，严重度是 `[高]/[中]/[低]/[未分级]`（认不出来的标「未分级」，不当下调成低）。
4. **下一步**——失败时给补救办法；成功时说明还能做什么（换范围、看会话）。
5. **出处**——引擎、路由（模型 provider/model、来自当前会话还是 DSH 默认）。
6. **附录**——被截断的输出、原始 JSON、落盘路径；这一层永远存在。

**失败时**：给结果码 + 下一步 + 费用说明。例如 `OCR_LLM_MISSING`：没有可用模型，**本次零调用、零费用**。

## 两个引擎

| 引擎 | 行为 | 成本 |
| --- | --- | --- |
| `ocr`（默认） | 跑 OCR 的完整流水线（确定性工程 × LLM 的 agent 流水线） | 按 tokens 计费；每文件 3~10 分钟；跑前给预估 |
| `delegate` | 不调 LLM，几秒产出「评审规格」（可审文件 + 规则 + diff），由当前模型自己审 | 免费（只用当前对话的模型） |

两个引擎都会先解析 ocr 可执行文件：`delegate` 用它生成规格，`ocr` 用它跑流水线。

## 模型从哪来

插件在 `127.0.0.1` 上开一个只监听本机、随机 token 的桥，ocr 的请求转发给 DSH 的 `llm.stream`：

1. 设置页里填了模型 → 用它；
2. 留空 → 用**当前对话正在用的模型**；
3. 再没有 → 用 DSH 默认模型；
4. 都没有 → `OCR_LLM_MISSING`（不跑、不花钱）。

provider 与 model 只会取**同一条路由**上的一对，不会跨 provider 拼。

## 设置项

设置页四个：**总开关 / 默认引擎 / 按需评审**，展开「高级设置」还有**模型名 / 提供方**。

模型名、provider、ocr 路径放在 `config.json`（留空 = 自动，见上一节）。改设置页立即生效，不需要重启。

## 常见失败

| 结果码 | 含义 | 怎么办 |
| --- | --- | --- |
| `OCR_NOT_FOUND` | 找不到 ocr 可执行文件 | 插件自带；非 win-x64 / mac-arm64 平台需自备一个，或在 config.json 设 `ocrPath` |
| `OCR_LLM_MISSING` | 没有可用模型路由 | 设置页选一个模型，或确认 DSH 有默认模型；本次零调用零费用 |
| `OCR_NOT_GIT_REPO` | 当前目录不是 git 仓库 | `git init` 或换工作目录 |
| `OCR_TIMEOUT` | 超时被终止 | 缩小范围（`scope=commit`）或调大 `timeoutMinutes` |
| `OCR_ABORTED` | 被取消 | 重跑；已产生的用量不退还 |
| `OCR_ALREADY_RUNNING` | 已有一个评审在跑 | 等它结束（同一时刻只跑一次） |
| `OCR_INVALID_ARGS` | 参数组合不支持 | 按提示里的正确用法重试 |

## 排障

- `ocr_status` 一条命令看全：ocr 从哪来（随包 / 本机）、路由实际用哪个模型、事件钩子挂没挂上、上次为什么失败。
- 按钮不出现：本回合没有代码改动。唯一例外是宿主读不到改动清单时——按 fail-open 一律显示。
- 想要更快反馈：设置页把引擎切到 `delegate`。

## 开发

```bash
npm install     # 顺带装上 ocr 的平台二进制（约 55MB，只在 node_modules 里，不进仓库）
npm test        # smoke / client-smoke / bridge-smoke / host-contract / killswitch / cordis-inject / 打包体检
```

- `npm run test:pack`：断言发布包里只有该有的文件。
- CI：`.github/workflows/ci.yml`，Node 20 / 22 / 24 × ubuntu / windows。

## 已知限制

- 二进制随包提供 Windows x64（macOS arm64 的包也在，但未验证）。
- 安装会下载约 57 MB（平台二进制包），不执行任何构建脚本。
- 真机验收只在 Windows x64 上做过（macOS / Linux 未验证）。
- 没有进度条（ocr 不吐增量进度），「还剩多久」只能是区间估计。
- 只看**改动范围**（git diff），不扫全仓历史问题。
